# YouTube Operating System — Personal KB

This repository is my personal YouTube operating system and knowledge base. It collects strategy, ideas, experiments, templates and research for building an English-language technical YouTube channel focused on real developer experiments, AI-assisted coding, Laravel/PHP, cloud engineering and developer business topics.

Core principle

Don't ask: "What video should I make?"

Ask: "What interesting thing can I test, discover or explain that another developer would genuinely want to watch?"

Current phase

- Phase: Validation (first 30–50 videos)
- Constraints: ~5–8 hours/week, €0 initial investment, no paid editing or voice, free tools where practical

Purpose of this repo

- Hold the channel strategy and rules (`strategy/`)
- Store ideas, backlog and written scripts (`content/`)
- Centralize research, titles and thumbnail learnings (`research/`)
- Keep a simple, manual analytics dashboard (`analytics/`)
- Capture product ideas and validation plans (`products/`)
- Provide reusable templates for videos, experiments and reviews (`templates/`)

Success criteria (hypotheses to validate)

- Can I repeatedly create videos that strangers choose to watch?
- Do some formats produce repeatable audience engagement and build distribution?
- Can a blend of audience, trust and products generate sustainable revenue over time?

How to use this repository

- Read `strategy/NORTH_STAR.md` to understand the long-term intent and constraints.
- Add ideas to `content/IDEAS.md` as soon as they occur.
- Pull 1–2 ideas into `content/BACKLOG.md` each week and follow the workflow in `templates/VIDEO.md`.
- Record experiments in `content/experiments/` and use `templates/EXPERIMENT.md` to capture evidence and follow-ups.
- After publishing, fill `research/LEARNINGS.md` and `templates/REVIEW.md` to separate facts from interpretation.

First 90 days (high level)

- Month 1: establish workflow, publish 4–8 videos, learn basic production.
- Month 2: iterate on titles, thumbnails and formats; track analytics.
- Month 3: review patterns, scale promising formats, kill dead ends.

Operating principle

- Prioritize real experiments, personal stories and demonstrable results over generic summaries.
- Treat this as a learning system: form hypotheses, run repeatable tests, record evidence, update strategy.

If anything in this scaffolding is unclear or missing, edit the appropriate file under `strategy/` or `content/` rather than creating a new ad-hoc file. Keep things simple and version-controlled.
